## 输入

- H02 的数据版本和快照范围、H03 的特征与缺失说明、H04 的验证预测及 H05 的验证群标记。9 日前可先写表头、合并检查和按群统计逻辑。
- 有群标记可先做历史行为画像。两份验证输出都到齐并核键后，再算复购与预测错误。

## 操作

1. 按 `customer_unique_id + snapshot_date` 对齐全量验证预测和群标记。先做唯一键与两侧未配对检查，回报影响行数和上游版本。缺关键输入时先交框架，标注缺口。
2. 逐快照逐群汇总客户数、正例数、模型和基线各自的入选数、命中数、漏判数。漏判是未来有合格订单但未进名单的人。各群沿用该快照的全局前 10% 名单；分群切片的分母分别为该群入选数、该群实际正例数。报小样本和零分母。
3. 和 2、4 号用实际验证期差异筛一项可在快照时计算的特征或交互。先核候选在久单群内是否有不同取值。给 3 号计算公式、动机、验证指标和预期影响，给 4 号指出异常群或画像缺口。
4. 3 号实施预测变更，4 号提供同一版群标记。你复核相同样本的前后对照，保留未改善的尝试。6 号据此定是否纳入汇报。最终评价结果用于记录效果和限制，禁止回流到选择阶段。

## 输出和验收

- 8 日交 `segment-evaluation-plan.md` 与最小表结构。10 日给 3、4、6 号 H06，交 `segment-errors.csv`、`feature-proposals.md`。12 日补 `feedback-comparison.csv` 及采纳／放弃理由。
- 每期各群加总须与 3 号原始验证名单及总体正例数核齐。表中分母明确，群号可回查聚类版本，特征公式无未来字段。
- 13 日交组内发现与前后对照的 Slides、英文讲稿、报告要点。未验证的提案写成下一步。

Agent 可先用人工小样例验证接口和统计逻辑，交付时区分真实结果与样例。
