# 方法设计：从历史订单到有边界的商业结论

## 1. 总体原则

主线是复购分类预测；辅助线是对全部符合条件的客户类型聚类并开展组内 EDA。组内发现可以回到特征工程，也直接形成客户洞察。**完整反馈流程尚未做完**，仓库中已有的是数据准备和两个独立的小实验。

最终使用一个面向全体客户的分类模型作为当前主方案；没有默认每个群都训练一个模型。若以后探索分群专属模型，必须另外比较样本量、过拟合及实际收益。

## 2. 一个客户快照怎样形成？

以 2018-04-01 为分析时点：

- 历史窗口为 `[2017-10-01, 2018-04-01)`，左边包含、右边不包含。
- 只纳入历史窗口中有至少一笔已批准、商品金额合计为正订单的客户。
- RFM 等特征仅从历史窗口计算。
- 标签窗口为 `[2018-04-01, 2018-06-30)`，正好 90 天。
- 标签窗口中同一个 `customer_unique_id` 再出现合格批准订单，记为 1，否则记为 0。

这里用批准时间来定义订单事件。结果窗口足够长不等于观察到了该客户所有平台上的购买；我们只观察 Olist 文件中的记录。公开数据末尾月份稀疏，也不能仅凭最大日期就认定覆盖完整，本实验刻意把测试结果窗口结束在 6 月。

没有后续完整 90 天的客户，不应简单记为不复购。“未来没有看到结果”与“结果为零”不同，这叫观察不完整／右删失问题。

## 3. 当前 11 个预测特征

| 特征 | 人话定义 | 重要限制 |
|---|---|---|
| R | 距最近一次批准订单的天数 | 不是客户流失天数 |
| F | 历史窗口不同订单数 | 不数商品明细行 |
| M | 历史窗口商品金额合计 | 不等于利润，当前不含运费 |
| average_order_value | M 除以 F | 与 RFM 有派生关系，不是独立新证据 |
| max_order_value | 最大一笔历史订单金额 | 可能受极端订单影响 |
| average_item_rows | 每笔订单平均明细行数 | 不应未经核验叫不同商品数 |
| freight_share | 运费合计除以商品金额与运费合计之和 | 是买家记录的运费负担，不是物流成本 |
| observed_history_days | 距历史窗口内首次订单的天数 | 不是客户真实注册时长或完整客户寿命 |
| recent30_orders | 最近 30 天不同订单数 | 窗口在预测时点前 |
| recent30_spend | 最近 30 天商品金额 | 不包含未来订单 |
| state | 最近历史订单的客户州代码 | 类别，不代表数值大小 |

主键、买家 ID 和标签不进入模型。我们不使用未来配送日期、未来评分，也不按最终取消状态筛掉早先样本。后者会让历史决策偷看后来发生的事情。

## 4. 训练、验证和测试分别干什么？

| 阶段 | 快照日 | 历史开始 | 90 天标签截止，不含当天 | 用途 |
|---|---|---|---|---|
| 训练 | 2017-10-01 | 2017-04-01 | 2017-12-30 | 学习模型参数 |
| 验证 | 2018-01-01 | 2017-07-01 | 2018-04-01 | 选择设置、树数和候选方法 |
| 测试 | 2018-04-01 | 2017-10-01 | 2018-06-30 | 评价冻结后的方法 |

同一客户可出现在不同历史快照，这是已有客户被定期评分的场景。ID 不作为特征；标签窗口不重叠。但它不是专门评价从没见过的新客户。若研究新客户泛化，要按买家分组另做拆分。

一旦看过测试结果，它就成为探索证据。后续若据此改变思路，不能把同一个测试时期继续称为完全未触碰的确认性测试。最终研究需保留新的评估方案或多时间窗口，并清楚交代探索过程。

## 5. 分类模型怎么工作？

- **逻辑回归**：给历史特征组合成一个分数，再转成 0–1 输出。结构简单，易作基准。当前对数变换、标准化数值特征，州代码转 one-hot。
- **随机森林**：多棵决策树分别根据条件做判断，汇总结果。能处理非线性，但复杂不保证优于简单方法。
- **CatBoost**：逐步添加树来纠正前面的预测误差，并能处理类别信息。
- **HistGradientBoosting**：另一种基于树的提升方法，用分箱等方式提高效率。

当前每个新增模型仅试两个预先选定设置；CatBoost 试三组设置。以验证集 AP 选取，不按测试集表现调参。选定后用训练＋验证快照重训，保持已选设置，再评价测试时期。

类别权重让少数类错误在训练损失中更受重视，但不创造新信息。加权后分数尤其不能直接当成已校准的真实概率。当前实验中加权设置没有取得最高验证 AP，这不是加权普遍无效的证明。

## 6. 四项指标怎么读？

设名单选择排名前 10%，测试客户数为 N；取 `ceil(0.1*N)` 人，ceil 表示向上取整。分数相同用客户编号作确定性排序，仅用于复现，不作特征。

| 指标 | 问题 | 注意 |
|---|---|---|
| Average Precision，AP | 在不同排名门槛下，能否把正样本排在前面 | 是精确率随召回增加的加权汇总，不是准确率；也不应与任意 PR-AUC 数值混称 |
| ROC-AUC | 一个随机正样本是否通常排在随机负样本之前 | 0.5 近随机；少数类场景不能单独使用 |
| Precision@10% | 选中的名单里，多少人实际复购 | 命中人数除以名单人数 |
| Recall@10% | 全部实际复购客户里，名单找到了多少 | 命中人数除以总复购人数，不是模型最大召回率 |

真实实验：逻辑回归选出 3,782 人，命中 73 人，总复购 299 人。因此精确率 `73/3782=1.93%`，召回率 `73/299=24.41%`。两者分母不同。选更多人一般能覆盖更多复购者，但会增加接触成本、降低名单集中度。

## 7. 聚类及组内 EDA 怎样与预测连接？

正式计划是：

1. 在开发客户的历史特征上选择聚类输入并拟合预处理。
2. 用 K-means 把相近客户分组；不把未来复购标签作为聚类输入。
3. 检查分群规模、离群样本和重复运行稳定性。
4. 对各群分别计算购买特征、验证期复购比例、模型错误和辅助品类画像。
5. 把组内发现变成少量候选特征、交互项或客户群标记。
6. 在相同开发／验证设计下比较初版与修改版，记录无改善的尝试。
7. 冻结方法后，再做最终测试；同时输出客户画像和业务解释。

K-means 根据输入空间中的距离分组，数值单位会影响距离，所以要变换／标准化。若用 RFM 分群，再发现各群的 RFM 均值不同，只是在重复定义。解释价值还要看稳定性、额外变量和具体决策。

如果类别变量参与聚类，需要选择合适编码和距离；不能把州代码编码成 1、2、3 后当连续数值。当前小实验只用数值 R/M 或 RFM。

## 8. Category lift 与稳定性

Category lift 是某群买过某品类的客户占比，除以整体客户相同占比。例如 30%／15%=2，表示已观察到的购买比例是整体两倍。这是假设例子，不是营销提升两倍。需要报告人数、分母、窗口、缺失品类；多次购买的人更容易覆盖多个品类，可能造成混杂。

轮廓系数看群内接近、群间分离；ARI 看两次分组的一致性并校正随机一致。ARI 接近 1 表示两套分组类似，不是分类准确率。种子改变检验初始化敏感性；重抽样检验样本变化敏感性；跨时间客户行为变化又是另一个问题。

## 9. 商业结论怎样写才站得住？

分开两条证据：预测是否更好；画像是否有用。不能要求聚类必须提高模型分数才能有意义，也不能因为画像好讲就忽略不稳定。

推荐结论模板：

> 在限定历史样本中，群体 A 的某项行为与整体不同；差异在若干检查下保持。运营团队可以考虑测试某项行动。我们尚未观察到干预记录，因此实际收益与成本需要后续对照实验确认。

目前不承诺最优模型、增加收入或提高真实复购率。数据年代、平台覆盖、极低正样本比例和选择偏差都是结论的一部分，而不是报告最后才补的一句免责声明。
