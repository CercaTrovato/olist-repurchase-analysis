2026-11-11。6 号已确认按全体同容量命中为主、久单覆盖作诊断的路线推进。本地和组员围绕同一组问题独立验证。本页是可供 6 号分发的任务包，实际分发和成员承诺另记。

## 共同需要回答的问题

1. 模型比最近购买、多单优先等简单规则额外找到了多少复购者，差异是否可靠？
2. 引入预测日已经知道的配送、评价或成员自主提出的历史信息后，能否改善全局排名，以及久单群内的排名？
3. 哪些评价窗口有足够覆盖？已有结果被查看后，结论能推广到什么范围？
4. 三群画像怎样形成一项有样本支持、可执行的内容试验假设？

组员可以自主设计字段组合、变换、规则和学习器。保留本人选择的理由、完整尝试与失败结果，交付同口径对照后再与本地实验比较。模型名称、参数和“必须达到某个分数”均不作为成员验收条件。

## 主比较固定口径

- 输入 H02-v2-candidate-reviewed。训练 2017-10-01，开发验证 2018-01-01。现有 H05-km3-v1 群号用于共同切片，自己提出的分群可另作附加实验。
- 一月 29,368 人、230 正例。主键 customer_unique_id + snapshot_date，零重复、无漏配。统一客户池，缺失处理也须覆盖所有人。
- 每法全局选 2,937 人。分数降序，同分按匿名客户键升序。另在久单群里单独选 79 人。后者是一项群内诊断。
- 容量敏感性统一报 5%、10%、20%，对应 1,469、2,937、5,874 人。
- 保留原八字段加权逻辑回归对照，补最近购买和多单优先后按最近购买的规则。已有可复用分数先核版本。
- 配送、评价、聚合和编码都按预测日截断。对照期间预处理、填补、特征筛选只在训练侧拟合。
- 四月结果此前已被查看，已有数字作为补充评估记录。第三轮方法选择使用十月和一月。附加时间回测须事先列日期、标签成熟、既有曝光及窗口重叠，不以换一个快照日期宣称新盲测。

H02_candidate_v2.zip、H04_role03_prediction_v0.4.zip 和 H05_role04_2026-11-10(1).zip 沿用组内已分发附件。逐人文件从组内渠道取得，缺文件时明确报给 6 号。下面的 [输入指纹清单](input-versions.csv) 和 [参考模型配置](reference-model.json) 用于核版本。H04 v0.4 的训练配置与 v0.2 相同，内部仍保留 model_source_version。原始 Olist CSV 按仓库 [数据来源](../../../data/README.md) 获取。

各方法可以自主设计，参考配置为原八字段、数值 log1p 后按训练集标准化、state 独热编码，以及 C=1.0、max_iter=2000、random_state=2026、class_weight=balanced。记录本人 Python/库版本和线程设置，数值误差与名单差异分别核对。

## 交付格式

组内逐人 CSV 至少包含客户键、快照日期、模型版本、分数、全局入选标志。交接说明写输入版本/哈希、字段公式、日期边界、参数、种子、命令和已知缺口。5 号以 H02 标签和 H05 群号独立连接复核。公开材料只交经核查的汇总与图表。

每个关键结论尽量配一张图，同时交图的汇总数据和生成入口。写清标题、日期、人数/分母、名单容量、比较对象和一句局限。PNG 适合直接放 PPT，SVG 适合后续编辑。随机种子波动和不同时间窗口分别解释。
