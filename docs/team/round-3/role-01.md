# 1 号 · 数据时点与时间有效性

[共同规则](README.md) · [当前进度](../current-status.md)

本轮要使成员能够安全使用新的历史信息，并知道能评价哪些时期。H02 和四月覆盖已有验收，先复用已有成果。

输入为原始订单、商品、客户、配送与评价数据，以及 H02 窗口定义。输出一份字段时点审计，说明每项信息在预测日是否已发生、如何连接、缺失怎样解释。评价使用答复时间，配送使用实际送达时间，按订单先聚合后接客户，避免明细倍增。预计送达日期的可知性假设须写清。

交付候选评价日期的时间表，列历史起止、90 天目标结束日、训练标签成熟日、原数据尾部与每日覆盖、与已见一月和四月目标区间的重叠。你可自行提出合适的时间验证设计，并解释其局限。窗口内某天没有合格订单应调查原因，不能仅凭这一点判定缺失或完整。

交给 2、3、4、5 号的文件建议为 field-time-audit.csv、time-window-audit.csv、数据版本及重算入口。至少配一张可读的时间边界图，图里标明已见的评价时期。

验收看组合键、窗口边界、原始行数和连接前后行数，禁止把未来已知的最终状态作为当时输入。已知且可算的字段定义交给 2、3 号，未解决部分单列。

给 Agent 的示例指令

> 请读取第三轮共同规则，复用现有 H02 核验，审计新字段的预测时点并提出时间验证方案。输出带边界与假设的字段表、时间窗口图及可运行脚本，不必追求某个模型分数。
