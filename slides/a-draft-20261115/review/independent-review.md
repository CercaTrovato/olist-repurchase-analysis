## 2. 需定向修正的发现

### A-R1：三群的生成方法没有交代

第 3 页列出三群人数与画像，但全部页面、讲稿和备问答没有说明这些群由何方法形成。普通经理可能以为这是按 37／135 天等中位数人为划分的硬规则。仅说这些是群体描述，仍不足以回答“怎么分出来的”。

应在第 3 页脚注／讲稿补最短必要解释，在备问答留一句完整方法。源 `role03/build_training_clusters.py` 可核：只取十月客户，输入为 `R, log1p(F), log1p(M)`，经 StandardScaler 后做三群 KMeans（`random_state=42, n_init=20`）；固定 H05 标签映射为较近单单／较久单单／多单。R3 README 说明两期群号与原 H05 全部一致。建议面向经理说明“把购买历史相似的人聚在一起，群名描述典型画像而非人人满足的硬条件”，具体十月拟合／一月映射细节按原 H05 来源核定后放备答。不要临时重做聚类或把 3 群写成已证明最优。

### A-R2：结尾讲稿超出同稿的正常速度预算
